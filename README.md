# metla 🧹

**Zero-nonsense disk sweeper для macOS.** TUI на Rust, который быстро индексирует диск,
показывает, кто съедает место, сам предлагает, что выкинуть или заархивировать, и делает это
в один-два нажатия. То, чего не умеет OmniDiskSweeper: массовая чистка мелочи и архивация
вместо удаления.

```
 metla ▸ ~ · 480G disk · 1.1T apparent    [1 browse] [2 hogs] [3 suggest] [t dark]
┌ ~/Work/myapp · 484M · 3.7K files ─────────────────────────────┐
│  NAME                                  SIZE         FILES     │
│▸ target · rust target                  484M  ██████████  3.7K  │
│  src                                   144K  ░░░░░░░░░░    14  │
│  Cargo.lock                            20K   ░░░░░░░░░░        │
└───────────────────────────────────────────────────────────────┘
 indexed 2.1M files · 145G in 18.0s · freed 3.1G today
```

## Реальный объём, а не эфемерный

По умолчанию metla считает и показывает **физический размер** — сколько байт реально
лежит на диске (`st_blocks`), как `du` без `-a`. Это важно именно на macOS:

- **iCloud Drive / Dropbox / OneDrive** («выгруженные» файлы) рапортуют полный логический
  размер, хотя на диске их нет вовсе — apparent size на такой системе рисует 5–10 ТБ
  на терабайтном диске. Физический размер таких файлов ≈ 0, и в сводке они честно не
  участвуют.
- **APFS-клоны** (Finder-дубликаты, `cp -c`) делят блоки, но оба файла рапортуют полный
  размер — apparent их удваивает.
- В шапке всегда **оба числа**: `480G disk · 1.1T apparent` — разрыв между ними это и
  есть история про облако и клоны. Клавиша `p` переключает режим, режим помечен в шапке
  колонки (`SIZE` / `PHYS`).
- Эвристики и оценки «сколько освободим» тоже работают в физических байтах, плюс есть
  guard: облако-плейсхолдеры (большой apparent, ноль на диске) не предлагается
  архивировать — архивация такого файла форсирует полное скачивание.
- При сканировании `/` автоматически пропускается `/System/Volumes` — firmlinks иначе
  задваивают весь дата-том (тот же контент доступен через корневые `/Users` и т.д.).
- **Облачные деревья (`~/Library/Mobile Documents`, `~/Library/CloudStorage`) пропускаются
  по умолчанию.** Там нечего освобождать (выгруженные файлы занимают 0 на диске), а каждый
  `opendir` в placeholder-каталоге ходит в File Provider daemon и способен подвесить скан
  на минуты. Нужно посмотреть, что лежит в облаке, — запусти metla явно на этот каталог
  (`metla ~/Library/Mobile\ Documents`): явный путь никогда не скипается.

## Зачем

- **Быстро.** Параллельный индексер (rayon, таск на директорию): ~2.1M файлов / 145 ГБ
  домашнего каталога разработчика за ~18 с. Сисколлы (lstat) — узкое место, аллокации — нет.
- **Видно всё.** Дерево с пропорциональными барами, топ-300 самых жирных файлов системы
  (`2 hogs`), сортировки по размеру / имени / дате / числу файлов, фильтр по подстроке,
  логические и физические размеры, дедупликация хардлинков.
- **Suggest-ы.** Движок сам находит: `node_modules`, rust `target`, DerivedData, кэши,
  симуляторы, толпы мелких старых файлов («квадро-огромная» чистка, которой не хватает
  OmniDiskSweeper), старые тяжеловесы, протухшие архивы, гигантские логи. По каждому —
  рекомендация `DEL`/`ARC` и байт-оценка.
- **Два действия.** `d` — удалить навсегда (мимо Корзины, намеренно), `a` — заархивировать
  в стриминговый `tar.zst` (память плоская), потом освободить. Восстановление:
  `tar --zstd -xf <архив> -C <где-лежало>`.
- **Две темы.** Тёмная и светлая, переключение на `t` на лету.

## Сборка и запуск

```bash
make release          # → target/release/metla
./target/release/metla            # сканирует $HOME
./target/release/metla ~/Work    # конкретный каталог
./target/release/metla --light    # светлая тема
./target/release/metla --scan-only ~   # без TUI: топ-жирных + подсказки в stdout
make check           # fmt + clippy -D warnings + тесты — гейт перед коммитом
```

> **Full Disk Access:** для индексации `~/Library` и подобных мест дай терминалу
> (iTerm/Terminal/...) Full Disk Access в System Settings — иначе APFS тихо отдаст не всё.
> Это ограничение macOS, не metla.

## Клавиши

| Клавиша | Действие |
|---|---|
| `1 / 2 / 3` | дерево / топ-жирных / подсказки |
| `↑↓ jk`, `pgup/pgdn`, `g/G` | движение |
| `enter / l`, `u / h` | внутрь / наверх |
| `space`, `X` | пометить / снять все метки |
| `d` | **удалить навсегда** (mимо Корзины) — с confirm-диалогом |
| `a` | **архивировать** в `~/metla-archive/metla-<ts>.tar.zst`, затем освободить |
| `/` | фильтр по подстроке в текущем списке |
| `s` | цикл сортировки: размер → имя → дата → число файлов |
| `p` | физические (по умолчанию, реально на диске) ↔ логические (apparent) |
| `t` / `?` / `q` | тема / помощь / выход (во время операции `q` — отмена, см. ниже) |

В подсказках: `space` — отметить строки, `d`/`a` — действие по отмеченным,
`D`/`A` — по всем найденным.

## Архитектура

Стиль — как у [qeli](https://github.com/litvinovtd/qeli): **типизированное ядро-библиотека
без UI** + тонкий TUI-клиент. Ядро не знает про терминал; UI не знает про файловую систему.

```
src/
  types.rs     newtype-скаляры: NodeId(u32), Bytes, UnixTime, NodeKind — всё Copy
  arena.rs     дерево = один Vec<Node> + пул имён (Vec<u8>); линки parent/child/sibling — u32;
               агрегаты размеров считаются снизу вверх итеративно; удаление — томбстоун FREED
               с декрементом предков, O(depth+subtree)
  walk.rs      параллельный обход: rayon-таск на директорию, один lock на батч директории;
               хардлинки дедуплицируются через (dev, ino)-таблицу; симлинки не разворачиваются
  junk.rs      классификатор мусора, срабатывает прямо во время обхода (у него уже есть
               контекст сиблингов: target + Cargo.toml → rust target)
  suggest.rs   чистая функция над ареной: толпы мелочи, старые тяжеловесы, протухшие архивы,
               логи; O(N) в caller-owned scratch-вектор
  archive.rs   стриминговый tar.zst (tar + zstd), память не зависит от объёма
  action.rs    план действий: dedup вложенных таргетов + safety-net (см. ниже) → execute()
               на worker-потоке над owned-данными, прогресс через атомики
  ui/          ratatui: state-машина (screens/modals/jobs), рендер видимого окна списка,
               палитры DARK/LIGHT, рендер-путь переиспользует scratch-буферы — без аллокаций
```

Честная рамка «zero-alloc»: горячие пути ядра (сортировка, фильтрация, подсказки, пути)
не аллоцируют — всё в буферах, переиспользуемых между кадрами; индексация аллоцирует только
амортизированные аппенды в две большие арены (узлы + имена). Форматирование видимых строк —
пара десятков мелких транзиентных аллокаций на кадр, это шум.

Стоимость памяти: ~72 байта на узел → миллион файлов ≈ 70 МБ + пул имён.

## Безопасность

- `d` не переносит в Корзину — это осознанный дизайн инструмента-метлы; поэтому каждый
  действие идёт через confirm-диалог со списком целей и байтовыми оценками.
- **Каждая операция пишется в лог** `~/.metla/metla.log`: verb, статус (ok / partial /
  cancelled), освобождённые байты, путь архива и по строке на каждую цель (done/fail).
  «Что это было?» — смотреть там.
- **Отмена**: `q` или `Esc` во время операции просит воркер остановиться — он завершает
  текущий item и не начинает новые. Уже созданный частичный архив подтирается, не тронутые
  цели остаются на месте. Тост после отмены — красный: план выполнен не полностью.
- Во время операции Working-модалка показывает **какой именно путь обрабатывается** —
  даже когда план из одного огромного файла (тогда items-прогресс 0/1 не двигается,
  путь — двигается).
- **Активные файлы**: если файл занят запущенной VM/базой (colima, Docker, эмуляторы) —
  сначала остановите процесс (`colima stop`), иначе место от удалённого файла не
  освободится, пока дескриптор открыт, а VM будет продолжать писать.
- **Safety-net** отклоняет: `$HOME`, корень сканирования, каталог архивов, всё, что содержит
  каталог архивов, и системные префиксы `/System /bin /sbin /usr /dev /private/etc
  /private/var/db /private/var/vm`. Отклонения показываются как warnings в диалоге.
- Вложенные цели дедуплицируются: если помечен родитель и ребёнок, удаляется родитель.
- Архивация: сначала полный tar.zst, и только потом удаление оригиналов; любая ошибка —
  оригиналы нетронуты, битый архив подтирается.
- При сканировании `/` автоматически пропускаются `/dev /proc /sys` и `/System/Volumes`
  (см. «Реальный объём» — firmlinks).

## Правила подсказок (пороги в `src/suggest.rs`, `impl Default for Rules`)

| Правило | Условие | Рекомендация |
|---|---|---|
| known junk | `node_modules`, rust `target` (рядом `Cargo.toml`), `DerivedData`, `Caches`, `.gradle`, `.npm`, `__pycache__`, `~/.Trash` и др. | delete (регенерируемое) / archive |
| tiny crowd | ≥200 файлов ≤64 КБ каждый, суммарно ≤512 МБ apparent, **≥1 МБ реально на диске**, не тронуто ≥90 дней | archive |
| old heavyweight | файл ≥256 МБ **на диске**, не тронут ≥365 дней | archive |
| stale archive | `zip/7z/dmg/tar.gz/…` ≥10 МБ **на диске**, не тронут ≥180 дней | delete |
| big log | `*.log` ≥128 МБ **на диске** | delete |

Оценки «reclaimable» — физические байты. Правила по толпе и тяжеловесам требуют, чтобы
данные реально лежали на диске: выгруженные в облако файлы (apparent большой, на диске 0)
не предлагаются ни удалить, ни архивировать — metla не устраивает форсированных скачиваний.
